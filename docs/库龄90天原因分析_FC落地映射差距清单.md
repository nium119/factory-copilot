# 库龄 90 天原因分析 — FC 落地映射差距清单

> 依据：`库龄90天原因分析维度_AIAgent应用.xlsx`（12 归因维度 + 7 检测场景 + 专用化率规则）

> 现状本体：库存预测 namespace（10 概念）+ manufacturing namespace（59 概念）

## 一、结论先行

**能实现，但前提是补齐库存预测项目的本体建模。** 源库字段不缺（实测核对），缺的是「库存预测本体只映射了 10 张表、且字段取不全」。当前 FC 之所以查不到库存量/MRP/在途/变更日志，不是业务系统没有，是 OntoStudio 没把这些概念建模进来。

## 二、源库表 ↔ xlsx 需求 ↔ 本体现状 对照

### 维度 1：预测准确性（Forecast accuracy）
- **需要**：Forecast 版本/发布日期/需求数量/实际消耗/偏差率/冻结时间
- **源库**：`SDForecastMain`（BillNo/BillDate/FStatus）、`SDForecastEntry`（Qty/CommitQty/IsCover/bMrp/DeliveryDate）
- **本体现状**：MpsForecast/MpsForecastEntry 已映射，但**缺「版本快照/发布时间/调整记录」**
- **差距**：中 —— 有主数据，缺版本历史（需新增「Forecast 版本」概念或复用 remark 记录）

### 维度 2：订单取消/延期（Order Cancel/Reschedule）
- **需要**：SO 创建日期/原需求日期/变更日期/Cancel/Reschedule/Reduce 数量/原因
- **源库**：`SDSOMain`（BillDate/FStatus/bClose/Comment）、`SDSOEntry`（Qty/CommitQty/DeliveryQty/NotOutStockQty）
- **本体现状**：WmsSaleOrder/WmsSaleOrderEntry 已映射，但**缺「变更日志」**（Cancel/Reschedule 时间戳+数量）
- **差距**：中 —— 缺 SO Change Log 概念（源库无独立变更日志表，需从 FStatus/bClose + 时间戳推导，或建变更快照）

### 维度 3：MPS 主生产计划
- **需要**：MPS 版本/调整日期/计划数量/实际生产/取消减少数量/冻结日期
- **源库**：`MPSForecast`、`MPSForecastEntry`、`MPSForecastEntryItem`（已映射）
- **本体现状**：已映射，但缺「MPS 版本快照时间线」
- **差距**：中 —— 主数据有，缺版本历史

### 维度 4：MRP 参数（关键缺口）
- **需要**：MRP 运行日期/建议量/计划订单/MOQ/LT/安全库存/批量规则/参数变更
- **源库**：`MPSMRPResult`（addtime/startdate/enddate）、`MPSMRPResultEntry`（stockqty/shortQty/suggestQty/totalneedQty/needQty）、`MPSMRPPlan`（qty/date/tranqty/trantype）
- **本体现状**：❌ **完全没映射**
- **差距**：大 —— 需新增「MRP 结果」「MRP 结果分录」「MRP 计划」3 个概念

### 维度 5：交付灵活性（Delivery flexibility）
- **需要**：PO 计划到货/供应商确认交期/实际到货/提前超交数量
- **源库**：`ArrivalOrderMain`（BillDate/checkUserId/FStatus）、`WMS_PoArrival`（ArrQty/InQty/NotInQty/PoEntryId）、`PurchaseOrderEntry`（DeliveryDate/InStockQty/NotInStockQty）
- **本体现状**：PurchaseOrderEntry 已映射（有 DeliveryDate/InStockQty/NotInStockQty），但**缺收货单概念**
- **差距**：中 —— 分录有到货字段，缺收货单/到货单独立概念

### 维度 6：采购合同条款
- **需要**：合同生效/失效/MOQ/固定周期/批量/价格阶梯
- **源库**：`PurchaseOrderMain.ContractNo`（仅合同号，MOQ/条款需关联合同表）
- **本体现状**：PurchaseOrderMain 有 ContractNo，但**无合同主表概念**
- **差距**：大 —— 需新增「采购合同」概念（源库有 Contract/ContractDetail 表）

### 维度 7：库存准确性（关键缺口）
- **需要**：收货批次/账面数量/盘点数量/调整记录/最后移动日期/冻结状态
- **源库**：`MMCurrentStock`（Qty/BaseQty/OnPassageQty/InDate）、`CurrentStock`（IQty/AvaQty/LockQty/LastInDate）、`WMS_CurrentStock`（Qty/CreateDate）

- **差距**：大 —— 需新增「库存」「库存流水」概念（源库有 WMS_RecordEntry/TransVouch 等流水表）

### 维度 8：新产品开发（NPD）
- **需要**：项目编号/阶段/试产量产需求/延期取消日期/BOM 版本
- **源库**：`MPSProject`（项目）、`SDSOMain.ProjectName`
- **本体现状**：❌ 未映射项目概念
- **差距**：大 —— 需新增「项目」概念

### 维度 9：产品生命周期（PLM/EOL）
- **需要**：EOL 通知/生效日期/产品状态/替代料/切换计划
- **源库**：源库未见独立 EOL 表（需确认，或用 Product 状态字段）
- **本体现状**：❌ 库存预测无，manufacturing 有 ECN 但无 EOL
- **差距**：大 —— 需确认源库 EOL 数据落点

### 维度 10：客户生命周期

- **本体现状**：WmsSaleOrder 有 customerNo，但无「客户」概念
- **差距**：中 —— 需新增「客户」概念（源库 MDM_Customer 有）

### 维度 11：ECN 工程变更
- **需要**：ECN 通知/发布/生效日期/新旧 BOM/替代料/旧料截止日期
- **源库**：`PFEP_ECN`（VoucherNo/VoucherDate/Status/StatusDisplay）、`PFEP_ECNEntry`（Qty/ValidBegin/ValidEnd/ItemNo）
- **本体现状**：❌ 库存预测无；manufacturing 有 ECN/ECNItem/InventoryImpact/MaterialReplacement（字段已对齐！）
- **差距**：小 —— manufacturing 的 ECN 概念已具备，库存预测场景复用即可

### 维度 12：框架订单/交付计划（Blanket）
- **需要**：Blanket PO/Release Date/Daily Schedule/供应商确认/收货
- **源库**：`DeliveryPlan` + `DeliveryPlanItem`（交付计划表）
- **本体现状**：❌ 未映射
- **差距**：大 —— 需新增「交付计划」概念

## 四、专用化率（工作表 3）的计算依赖

专用化率 = 该物料未来有效需求 ÷ 物料全部未来需求，需要：
1. **物料全部未来需求**：Forecast + MPS + SO 的未来需求聚合（有，但需聚合逻辑）
2. **其他客户/产品需求**：按客户/项目维度切分（需「客户」「项目」概念）
3. **BOM 用量换算**：BaseBom/BaseBomEntry 有（✓）
4. **净影响量 = MAX(0, 取消量 - 可吸收量)**：需规则引擎 computed 或分析链

**差距**：核心是「客户」「项目」概念缺失 + 聚合计算逻辑（不是查询，是算法）。

## 五、落地路径建议（分三阶段）

### 阶段 1：补本体建模（OntoStudio，不写代码）
按优先级补齐库存预测 namespace 缺失概念：
1. **库存**（映射 MMCurrentStock/CurrentStock）—— 解维度 7、所有场景的「库存量」刚需
2. **MRP 结果**（映射 MPSMRPResult/Entry/Plan）—— 解维度 4、场景 6
3. **采购收货/在途**（映射 ArrivalOrderMain/WMS_PoArrival）—— 解维度 5、在途量
4. **客户**（映射 MDM_Customer）—— 解维度 10、专用化率
5. **项目**（映射 MPSProject）—— 解维度 8、专用化率
6. **销售订单变更日志**（从 SDSOMain/SDSOEntry 的 FStatus/bClose 推导或建快照）—— 解维度 2
7. **ECN**（复用 manufacturing 或映射 PFEP_ECN）—— 解维度 11

### 阶段 2：归因算法固化（FC 规则引擎 + 分析链）
把 xlsx 的「关键日期判断 + 影响数量计算 + 贡献率 + 专用化率 + 净影响量」固化成：
- **规则引擎 trigger/computed**：MRP 多采购检测、EOL/ECN 预警、专用化率阈值
- **分析链**：订单取消影响、延期影响等场景的确定性归因链路（PO Date vs 事件 Date 判断）

### 阶段 3：自动触发 + 预警
- event_dispatcher / monitor_scheduler 检测源库新增 Cancel/EOL/ECN/MRP 记录
- 自动展开 BOM → 算净影响 → 推送预警 + 待取消 PO/待调整计划清单

## 八、归因算法落地（确定性规则，落到 FC 规则引擎/分析链）

### 8.1 关键日期判断（贯穿所有维度）

```
PO Date vs 事件 Date：
  事件 Date > PO Date  → 「事后需求变化」，归因于事件本身
  事件 Date ≤ PO Date  → 「已知变化仍采购」，归因于计划/采购执行问题
```
这是 12 个维度共用的核心判断，落地为一条公共分析函数。

### 8.2 专用化率 + 净影响量（工作表 3 核心）

```
专用化率 = 该物料未来有效需求 ÷ 物料全部未来需求
  专用化率 ≥ 80%  → 专用件（重点处理）
  50% ~ 80%       → 半专用件（按净影响处理）
  < 50%           → 通用件（可吸收则不处理）

净影响量 = MAX(0, 取消BOM需求量 - 其他可吸收需求量)
最终暴露量 = MIN(净影响量, 当前库存 + 在途 + 不可取消PO)
```

### 8.3 建议的规则引擎触发（trigger）清单

| 规则 | 触发条件 | 产出 |
|---|---|---|
